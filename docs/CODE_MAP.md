# Code map

Start here when changing Racall. [Development setup](DEVELOPMENT.md) · [Contributing](../CONTRIBUTING.md) · [Roadmap](ROADMAP.md)

The application is a modular desktop monolith: Electron starts one Python service and a static React interface. Feature folders contain the code for a user-facing section. Shared infrastructure stays small and explicitly named.

Python owns the application logic; TypeScript/JavaScript and CSS serve the interface
and desktop integration. See the [architecture boundaries](ARCHITECTURE.md).

## Shared infrastructure

- [API application](../apps/api/on_knowledge/app.py): service composition, startup/recovery, authorization, CORS, errors and static web hosting. Feature endpoints belong in feature routers.
- [Knowledge facade](../apps/api/on_knowledge/knowledge.py): stable entry point for API routes, MCP and workers. Retrieval lives in [retrieval/service.py](../apps/api/on_knowledge/retrieval/service.py), rank fusion/vector similarity in [retrieval/ranking.py](../apps/api/on_knowledge/retrieval/ranking.py), and answer/Research orchestration in [generation](../apps/api/on_knowledge/generation).
- [Ingestion facade](../apps/api/on_knowledge/ingestion.py): stable parser/import API. [Document models and limits](../apps/api/on_knowledge/documents/models.py), [local parsers](../apps/api/on_knowledge/documents/parsing.py), [text/Markdown blocks](../apps/api/on_knowledge/documents/text.py), [quote-preserving chunks](../apps/api/on_knowledge/documents/chunking.py), and [bounded public web fetching](../apps/api/on_knowledge/documents/web.py) have separate responsibilities.
- [Store](../apps/api/on_knowledge/storage.py): notebook paths, atomic file operations, retrieval database, audit log and a compatibility facade for notes. Note-specific file logic lives in the note repository.
- [Completion transport facade](../apps/api/on_knowledge/completion_stream.py): synchronous public API, HTTP ownership, idle/total deadlines and scoped cancellation. [Strict payload decoding](../apps/api/on_knowledge/completion/payloads.py), [bounded SSE framing](../apps/api/on_knowledge/completion/events.py), and [Chat Completions state machine](../apps/api/on_knowledge/completion/openai.py) live under `completion/`. [Providers](../apps/api/on_knowledge/providers.py) bind transport to model settings, execution-local credentials and safe diagnostics; embedding requests retain their separate transport.
- [Claude stream parser](../apps/api/on_knowledge/anthropic_stream.py): native Messages events, text-only JSON assembly and terminal-state checks. It shares HTTP/framing limits with the Chat Completions transport.
- [Web API facade](../apps/web/lib/api.ts): public imports for [HTTP client/error handling](../apps/web/lib/api/client.ts), [shared DTOs](../apps/web/lib/api/types.ts), [original-file retrieval](../apps/web/lib/api/source-files.ts) and [evidence location labels](../apps/web/lib/api/evidence-location.ts). [Desktop bridge types](../apps/web/lib/desktop.d.ts) describe the sandbox preload surface. Feature state belongs in its feature folder.
- [Markdown renderer](../apps/web/components/markdown.tsx): shared display component.
- [Translations](../apps/shared/locales): English and Russian catalogs. [Localization guide](LOCALIZATION.md).
- [Electron lifecycle](../apps/desktop/main.cjs): startup, single-instance handling and shutdown. [Runtime paths](../apps/desktop/runtime.cjs), [Python process](../apps/desktop/backend.cjs), [session/sender/navigation security](../apps/desktop/security.cjs), [window/theme/unsaved dialog](../apps/desktop/window.cjs), and [fixed native actions](../apps/desktop/native-actions.cjs) stay separate. [Preload](../apps/desktop/preload.cjs) exposes the narrow sandbox bridge; [locale](../apps/desktop/locale.cjs) handles native translations. [Installer](../installer) contains Windows installer customization.
- [Style composition](../apps/web/app/layout.tsx): preserve stylesheet order. [Globals](../apps/web/app/globals.css), [Racall overrides](../apps/web/app/racall.css), and [knowledge workbench](../apps/web/features/studio/knowledge-workbench.css) are ordered import entry points. Shared foundation/forms/overlays/responsive rules live in [app/styles](../apps/web/app/styles); section rules live beside their features. [Theme tokens](../apps/web/app/themes.css) remain a separate layer. Preserve cascade order when moving rules.

## Adding a section

Use matching feature names under `apps/web/features/` and `apps/api/on_knowledge/features/`. Place route handlers in `router.py`, substantial validation in `schemas.py`, workflow logic in a service, and file/database operations in a repository when that distinction is useful. A small feature does not need empty service layers.

Keep JSX focused on rendering; extract asynchronous state/lifecycle logic into a named hook when it has a distinct responsibility. Split by behavior and ownership, not by an arbitrary line count; small cohesive files do not need extra layers. Use explicit imports and names that explain the responsibility. Avoid catch-all `utils` or `manager` files and unrelated behavior in the application shell. Follow the [reference-project review process](REFERENCE_PROJECTS.md) before implementing a substantial new workflow.

Keep the public `knowledge.py`, `ingestion.py`, `completion_stream.py` and web `lib/api.ts` facades stable while maintaining their focused implementations. File moves must preserve request contracts, persistent paths, credential/cancellation scopes and stylesheet ordering.

## Windows installer styling

See `installer/README.md`: `appearance.nsh` controls light colors and typography, `assets/` holds logo bitmaps, and `scripts/build_installer_assets.py` regenerates them. The compact first screen lives in `welcome.nsh`, its translations in `catalog.json`, the reference window layout in `layout.nsh`, and the parent handoff in `selection.nsh`. Keep language seeding in `languages.nsh` separate from styling.

[Evidence references](../apps/api/on_knowledge/evidence_references.py) prepare short, request-local model citation labels. The [claim verifier](../apps/api/on_knowledge/claim_verification.py) validates accepted claim references; the [answer workflow](../apps/api/on_knowledge/generation/answers.py) restores canonical IDs before returning or saving an answer through the Knowledge facade.
