# Racall 0.2 Beta — release candidate preparation

**Not published. Publication is on hold at the owner's request.** The public download remains [0.1 Beta](https://github.com/SleepyCodeMeow/Racall/releases/tag/v0.1.0-beta.1). The working branch is `development/0.2`.

## Changes

- Persistent notebook chats with rename, selection, recoverable transcript removal, saved answers/search results and exact citation snapshots. Interrupted questions are visible after restart and are not automatically sent again.
- Markdown autosave, preserved frontmatter/aliases, recovery drafts, protection against external editor changes and a choice to save a copy. Newer typing survives delayed save responses. Unsaved notes block destructive notebook actions; cancelling close keeps the local service alive.
- Notebook rename and a recoverable notebook trash. Restoring brings back the original notes, chats and sources. Busy notebooks cannot be removed while model/import operations are active.
- Source file replacement and website refresh. Version history preserves past originals and normalized passages; old citations open their original version. Failed replacements retain the previous working source and search index.
- A dedicated parser process for files and web pages: 60-second deadline, supervised 512 MiB resident-memory budget, plus a Linux address-space cap. Failed/oversized parses do not run inside the API process.
- Feature-oriented UI/API folders, a [code map](../CODE_MAP.md), English/Russian controls and error messages.
- Opt-in [model evaluation kit](../MODEL_EVALUATION.md): four synthetic documents, ten EN/RU questions and a source-version update exercise.

## Validation and release status

Local backend regression checks, production frontend/frozen-service builds and the Windows maintenance scenario passed. Final packaged regression, four native CI targets and installer checks are tracked in the [release checklist](../RELEASE_02_CHECKLIST.md) and [verification record](../VERIFICATION.md). Real-model acceptance is intentionally left to the owner; no real-provider quality result is claimed from deterministic stubs.

## Limits

Saved chat history is not yet supplied as conversational context to the model. Changes that have not reached the service can be lost in an abrupt crash, and revision checks are not filesystem transactions with arbitrary external editors. Source versions and notebook trash are retained; no permanent-delete interface is included. Parser limits reduce resource risk but do not constitute a security sandbox.

Builds are unsigned and macOS builds are not notarized. CI checks do not cover every interactive OS permission/security dialog. Back up the full knowledge directory with the app closed before upgrading; 0.1 notebooks are supported on upgrade, but downgrading versioned 0.2 sources is not guaranteed.

No new release tag or GitHub Release has been created. Candidate installers are for validation; the existing 0.1 release is unchanged.
